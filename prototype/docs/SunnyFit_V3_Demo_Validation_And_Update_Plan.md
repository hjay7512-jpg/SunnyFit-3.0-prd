# SunnyFit V3 Demo 三轮验证结果与更新方案

日期：2026-10-12。交付对象：产品、设计、前后端开发与评审人员。

三轮审查提出的前后台优化已实施为本地 Demo，最新入口、行为和验收结果见 [优化版 Demo 交付说明](SunnyFit_V3_Optimized_Demo_Handoff.md)。以下保留审查时的基线、更新方案与真人测试协议；历史发现不代表当前仍存在相同缺陷。

本轮完成的是本地浏览器任务走查与接口状态核对，不是欧美用户研究。三轮分别是业务与实现审查、体验表达审查、可执行任务验证；前两轮意见经过用户纠正后才进入以下方案。未修改商业规则实现、现有 Demo 数据、生产环境、Confluence 或 Figma。

## 三轮结论和业务边界

| 主题 | 最新结论 | 下一版处理 |
| --- | --- | --- |
| 基础训练和记录 | 用户明确应用内基础功能免费。首轮关于整体免费承诺的风险降级。 | 保留免费路径；付费入口说明新增服务价值及仍可使用的基础功能，不要求增加全局解释流程。 |
| 会员与消费 | 权限与消费继续分开。用户提出周报等可预估服务由会员包含，不必全部消费 Credits。 | 将服务支持为会员包含、周期用量及额外消费等模式。服务矩阵和具体数量仍是待定参数。 |
| Program 组合授权 | 用户明确现有业务不会出现解锁 Program 后重复收费。 | 不再列为线上缺陷。下一版 Demo 的组合授权和文案应与现有实际业务对齐，不能沿用“组合授权待定”的演示口径冒充线上行为。实现所需具体授权映射需接入现有契约。 |
| 超额消费 | 用户提出订阅包含用量，超额允许另付费；额外购买 Credits 不设置过期。 | 作为下一版设计方向。订阅包含用量与额外购买余额分开展示；超额使用前明确确认，不自动扣款补充。 |
| 订阅流程 | 用户明确需要调整。 | 替换追加时长式购买，展示订阅、切换套餐、取消续费、生效时间及恢复购买状态。具体渠道结算规则不自行定值。 |
| 独立资产 | 既有确认：已有聊天、计划、分析、训练记录及独立兑换内容保留。 | 阅读不重新计费；新生成和新请求重新检查；订阅取消与到期分别验证。 |
| 周期版本 | 已购周期保留购买时承诺。 | 当前权益读取购买快照和有效授权；在售权益单独读取当前发布版本。 |

会员套餐价格、每类服务的包含量、重置周期、赠送额度与其到期规则、额外消费价格、内容兑换方式及渠道切换政策均未在本轮定为生产值。尤其“每月四至五次周报”不能直接硬编码为每月四次：按周生成与自然月次数需要选定一致定义。

## 第三轮任务验证

运行方式：当前源码生产构建、本地 Node API、独立 SQLite、Microsoft Edge 无界面浏览器。桌面评审视口为 1440 × 1200；补查 390 × 844 移动视口。

本轮证据：[机器结果与源码指纹](validation-round-3/2026-10-12T08-07-27-603Z-6ac7196f/results.json)。浏览器没有未处理页面错误，也没有意外失败的 API 响应。截图共 13 张。

### 任务一 判断训练是否包含

免费账户打开免费课程，Start 授权通过且不进入购买。免费账户打开订阅课程，Start 导向会员。付费账户独立兑换课程后，再次 Start 不再消费 Credits。

这证明入口授权和重复使用的消费规则成立，不证明播放器、训练完成或用户理解已经通过。课程播放器不在当前 Demo 中，授权成功的反馈显示在评审侧栏。

已解锁课程仍显示 `Featured · 30 Credits`。标签读取内容分类而没有反映用户访问状态。课程画面标题是 `25-Minute Beginner Cycle`，兑换弹窗却是 `The Signature Strength Session`：当前设计画面与场景 ID 分别绑定，侧栏已说明，但这使用户无法评估自己买的是哪一项内容。

证据：[已解锁仍显示价格](validation-round-3/2026-10-12T08-07-27-603Z-6ac7196f/04-unlocked-still-priced.png)、[免费 Start](validation-round-3/2026-10-12T08-07-27-603Z-6ac7196f/02-free-course.png)、[会员限制](validation-round-3/2026-10-12T08-07-27-603Z-6ac7196f/03-premium-gate.png)。

下一版应让列表、详情、报价和成功反馈使用同一内容对象。精选推荐和商业授权分为不同字段；已解锁显示 `Unlocked`，主按钮仍为 `Start`。不要仅靠标签颜色表达状态。

### 任务二 补充用量后完成分析

会员余额不足时出现 Credits 限制，未错误导向会员。完成模拟购买后返回 Workout Data，不自动执行分析；再次明确确认后消耗演示报价 8 Credits，产生一个新结果。刷新读取不扣费。模拟分析失败时释放预留余额，不增加资产。聊天草稿在钱包往返后也保留。

这条功能路径成立，但仍运行旧的“每项 AI 新使用扣 Credits”模型。新提出的订阅包含次数、超额消费和付费余额不过期还没有实现，因此没有把旧路径通过标成新模型验收通过。

当前购买弹窗明确写着 `30 days after each issue`，与新的额外购买不过期方向不同。返回只恢复页面和已有场景，分析对象与待执行动作尚无完整的数据契约；当前报告展示也按服务类型取结果，不能证明多个训练对象下的正确结果关联。

证据：[余额不足](validation-round-3/2026-10-12T08-07-27-603Z-6ac7196f/05-analysis-balance-gate.png)、[返回原页](validation-round-3/2026-10-12T08-07-27-603Z-6ac7196f/06-return-to-analysis.png)、[生成成功](validation-round-3/2026-10-12T08-07-27-603Z-6ac7196f/07-analysis-saved.png)、[失败释放](validation-round-3/2026-10-12T08-07-27-603Z-6ac7196f/08-analysis-failed.png)。

下一版将同一动作的包含用量、超额报价、余额、权限和恢复上下文一起传递。购买余额后不自动收费，返回具体对象并让用户明确继续；首次价格确认、变价和超额消费要可理解，普通聊天不应每条都重复弹出同样解释。

### 任务三 取消订阅后找回已购内容

从会员页关闭续费，会员仍有效且原截止日期不变。随后通过独立测试动作模拟周期结束，账户回到 Free；独立兑换课程、已有资产和仍有效余额保留。已兑换课程仍能通过 Start，聊天历史可从原历史入口打开，读取不扣费。

资产保留已验证，但完整查找任务尚未成立。首页个人中心入口只在评审侧栏显示缺少设计来源，未进入账户页；会员与钱包的访问借助评审目录或直接路由。已购内容没有经过用户可独立发现的入口验证，不能将已知课程地址可打开等同于用户能找到已购内容。

证据：[关闭续费](validation-round-3/2026-10-12T08-07-27-603Z-6ac7196f/09-renewal-off.png)、[到期后独立内容](validation-round-3/2026-10-12T08-07-27-603Z-6ac7196f/10-expired-unlocked-course.png)、[到期后聊天历史](validation-round-3/2026-10-12T08-07-27-603Z-6ac7196f/11-expired-history.png)。

下一版沿既有个人中心补齐会员与用量入口，在现有内容体系中增加已解锁查找路径，继续将聊天、计划和分析保留在对应原模块。不要为商业化另建一个替代所有历史入口的资产中心。

### 当前权益与在售权益

在隔离数据库将 Premium 发布为 v2，移除 Weekly AI Insights 并调整福利数量；Casey 的已购 v1 仍保留 Weekly AI Insights。会员页 `Included with Premium` 却读取 v2 的在售权益，列表不再包含周报。

服务端快照保护成立，前台承诺展示不一致。应分别显示 `Your current benefits` 与 `Available plans`；不能把第一个在售商品的权益当作当前用户的权益。

证据：[购买快照与在售列表不一致](validation-round-3/2026-10-12T08-07-27-603Z-6ac7196f/12-purchased-vs-sale-benefits.png)。

### 验证范围与交付检查

13 项功能检查通过，包含授权、兑换后重复使用、余额不足、补充返回、分析扣减、历史读取、草稿保留、失败释放、取消和到期。已有 13 项领域测试通过，覆盖目录、Scope 校验、配置草稿、版本和重启持久化。

390px 检查中页面宽度为 390px，手机内容框为 375px，没有页面水平溢出。放大字号、读屏、键盘焦点、支付中断和真实商店均未在本轮通过验证。

构建成功，有资源体积告警：入口约 1.13 MiB，一张课程图片约 11.3 MiB。交付前需压缩展示图片并重新检查加载体验。当前截图里的占位描述、画面与课程名称不一致也应清理；设计还原不意味着这些占位信息应成为产品文案。

| 页面 | 更新后的职责 | 关键状态 |

| 既有个人中心 | 进入会员管理、包含用量、额外余额；显示当前状态，不展示后台配置术语。 | Free、有效订阅、已取消但仍有效、到期、待确认。 |

| Usage and Credits | 展示订阅包含用量及重置时间，额外余额及不过期说明。 | 包含量充足、即将用尽、超额需确认、额外余额不足。 |
| 聊天 | 保持连续对话，显示当前消费方式；额外使用确认明确。 | 正常、包含量耗尽、超额、价格变化、失败、已有历史。 |

| 购买结果 | 返回原对象和原动作，显示真实履约状态。 | 支付取消、失败、处理中、支付成功待发放、完成。 |
| 已解锁查找 | 从既有内容导航找到独立获得的课程或 Program。 | 可用、到期或不可用说明；独立于当前会员身份。 |

既有四项导航和 AI 入口继续沿用。缺少 Figma 来源的个人中心补全采用明确标注的 Demo 提案，并与既有导航兼容；不声称提案已成为正式设计。

### 前台表达约定

1. `Featured` 只表达编辑推荐；访问标签反映内容与当前用户授权。单独购买显示 `Unlock · N Credits`，成功后显示 `Unlocked`。
2. 会员介绍使用用户收益和范围，不显示 `Courses · All` 等配置字段。价格旁说明实际扣款金额和周期，等效月价不能替代年付总额。
3. 有权限但用量不足时说明包含量已用完；缺权限时说明需要什么权益及该动作是否另有消费。两者都缺时一次说明完整条件。
4. 已有分析使用 `View insight`；新生成使用 `Generate insight`；重新生成明确属于新的请求。收费按钮显示消费方式或报价。
5. 额外 Credits 显示 `Extra Credits · No expiry`。批次、预留和扣减来源可在 Activity 详情查看，不占据钱包首页主层级。
6. 日期、币种、距离单位跟随地区设置；至少用美国和一个欧洲地区样例检查，不强制所有欧洲用户采用 en-US。
7. 取消、关闭和返回都保留用户输入和目标对象。购买成功不自动发起新的付费使用。

## 下一版后台与服务方案

沿现有目录、Suit、Product、SKU、Order、Grant 和有效权益结构扩展。后台配置、前台承诺、服务执行和运营追溯必须描述同一行为；不把所有字段继续堆进 Suit 的 Credits 福利。

| 能力 | 后台配置或查询 | 服务行为 | 前台对应 |
| --- | --- | --- | --- |
| 功能授权 | Item、Scope、Base 和 Additional，保留既有版本。 | 检查有效授权；消费不能替代权限。 | 是否能使用及缺少哪项权益。 |
| 会员包含服务 | 独立服务规则：服务、包含方式、数量、周期、版本；如周报每周一次。 | 检查当前周期与目标对象，防止重复领取或生成；读取结果不计新使用。 | Included、剩余次数、下一次可用时间。 |
| 周期包含用量 | 服务用量池及共享方式、重置锚点、时区、超额策略。 | 先使用适用的包含用量，记录预留、成功结算和失败释放。 | Included usage、重置日期。 |
| 额外购买余额 | 购买商品、数量与价格；无到期日期。赠送与其他来源单独定义。 | 支持无期限余额，按已定义优先级扣减；会员到期不清空。 | Extra Credits、购买和 Activity。 |
| 服务报价 | 包含或超额、报价版本、权限、目标对象、确认条件。 | 同一业务请求幂等；报价变更重新确认；不按内部工具调用重复收费。 | 当前动作真实费用。 |
| 订阅管理 | 渠道、计费周期、续费状态、当前有效期、待生效变更、支付与履约状态。 | 模拟渠道事件驱动演示，取消不等于到期；恢复不重复发放。 | Manage subscription、切换和恢复状态。 |
| 内容授权 | 商业访问方式、独立推荐字段、已解锁记录、Program 组合契约。 | 所有入口复用同一授权结果；按实际业务完成 Program 访问，不伪造重复收费。 | 统一标签、详情和 Start。 |
| 用户详情 | 当前权益快照、包含用量、额外余额、资产、请求、订阅与原因。 | 可解释用户为何被拦截及从何处扣减。 | 客服可对应用户看到的页面。 |
| 配置发布 | 草稿、差异预览、影响对象、版本。 | 已购周期与已有余额不因保存或发布被覆盖。 | 当前权益与在售权益分别显示。 |

### 数据契约和迁移顺序

后台实现落点如下，保持钱包、流水和资产在现有用户详情或相应模块内，不要求增加同名一级菜单。

| 现有文件 | 需要更新的字段或状态 |
| --- | --- |
| `src/views/commercialization/commerce-definitions.js` | 服务包含模式、超额策略、订阅周期定义；修正 Program 演示说明。 |
| `src/views/commercialization/configurations/detail.vue` | 会员包含服务与周期用量、无期限付费 Credits、SKU 计费周期及套餐变更规则；用显式不过期选项替代任意天数约定。 |
| `src/views/commercialization/users/detail.vue` | 当前权益快照、服务包含量与已用量、重置时间、额外余额、取消后有效期、请求最终扣减来源。 |
| `src/components/Commerce/Wallet.vue` | 周期用量与付费余额分组、Never expires、可到期赠送来源及流水详情。 |
| `src/views/commercialization/records/index.vue` | 包含用量消费、额外消费确认和报价快照、订阅变更与恢复结果，继续区分交易和履约。 |

建议增加服务消费策略及周期用量账本，而不是把 Credits 改名成次数。一次请求的结果应关联用户、服务、原对象、业务请求、使用来源、报价版本和生成资产。前台恢复上下文至少携带原页面、内容或训练对象、服务、输入和待确认动作。

付费余额不过期需要贯通配置校验、商品表单、批次存储、钱包汇总、消费排序、过期维护、购买报价和前台日期显示。当前实现要求有效期为正整数，消费查询依赖非空 `expires_at`；只去掉页面的有效期文字会造成余额不可消费或后台行为不一致。

迁移只针对 Demo schema 和测试种子先演示。已有会员周期、余额和资产保持原快照，不能运行全量清库或用新种子覆盖现有演示数据。是否调整历史已购余额期限必须作为明确迁移政策处理，不在本轮自动改写。

## 实施顺序和验收

### 第一阶段 修复展示与任务入口

先补内容身份一致、已解锁标签、当前权益快照、真实导航和准确 CTA。保持现有功能规则，形成能够独立走完三个任务的客户模式；评审工具可切换显示，但不作为用户完成任务所需导航。

主要位置：`src/views/app/index.vue`、`controller.js`、`SourceCanvas.vue`、`commerceMixin.js` 及现有内容组件。前台展示应由共享状态模型驱动，避免同一访问逻辑在多个页面重新推断。

验收：同一课程从卡片到报价名称一致；已解锁无再次购买暗示；旧会员看到自己实际权益；用户无需侧栏或直接 URL 即可进入会员管理并找到已解锁内容。

### 第二阶段 接入包含用量与额外余额

先建立版本化服务消费矩阵、无期限购买余额和周期账本，再更新后台表单、用户详情、钱包与前台服务入口。以周报作为会员包含服务的示例，以聊天或额外分析演示周期用量与超额确认，数值集中标明 Demo 配置。

主要位置：`server/store.cjs`、`server/commerce.cjs`、`server/catalog.cjs`、`config/demo-policy.cjs`、后台配置字段、Wallet 和 API 适配层。

验收：会员包含的周报不扣额外余额；周期边界和同一对象重复生成有明确规则；包含量耗尽后只有明确确认才扣额外 Credits；付费余额经过长时间模拟和会员到期仍可使用；失败、重试和并发不重复扣减；已生成结果读取免费。

### 第三阶段 完整演示订阅生命周期

实现订阅、取消、恢复、待生效套餐变更和支付履约分离。月付、年付采用可解释的 Demo 模拟渠道契约，明确演示与真实商店的边界；不继续默认所有购买都追加一段时长。

验收：当前套餐、下一次扣款、取消后的截止日期正确；套餐变更不意外产生重复订阅；恢复不重复发放；支付成功但权益待发放时不会显示已经可用；返回原对象并重新判断当前动作。

### 第四阶段 提高可用性和交付完整性

进行真实任务测试、移动设备检查、字号放大、焦点与读屏检查、加载和失败恢复检查。压缩大图片，替换占位文案，清理评审工具与正式用户反馈混用。

交付包含：规则状态表、服务消费矩阵、页面与 API 映射、数据契约、可运行 Demo、种子场景、测试命令、检查结果、截图、已知缺口和生产对接待办。文档与演示使用同一版本，不把尚未实现的设计方向写成已完成行为。

## 下一版需要覆盖的场景

| 场景 | 功能验收标准 | 体验验收标准 |
| --- | --- | --- |
| 免费用户开始训练 | 不进入支付，按基础授权进入现有训练流程。 | 用户能判断该训练免费。 |
| 会员包含训练 | 当前有效权益决定访问。 | 详情显示已包含，不暗示单独购买。 |
| 独立解锁和再次使用 | 一次兑换，不重复扣减，取消与到期不移除。 | 能从真实导航找到；看到 Unlocked。 |
| 会员包含周报 | 按定义周期生成，不扣额外余额。 | 用户知道已包含及何时可再生成。 |
| 包含用量耗尽 | 明确确认后按报价使用额外余额。 | 购买前知道本次费用与余额差额。 |
| 补充后继续分析 | 返回同一训练对象，不自动消费。 | 输入和目标保留，不重新寻找入口。 |
| 生成失败与重试 | 释放预留，幂等；不重复生成与扣费。 | 显示最终收费状态和明确重试入口。 |
| 取消与到期 | 两个独立状态；资产与余额按来源保留。 | 用户能解释结束日期以及留下的内容。 |
| 配置版本变化 | 已购规则保持，新购买用新版本。 | 当前权益和在售对比不会混淆。 |
| 套餐切换与恢复 | 契约明确，不重复订阅或发放。 | 用户理解生效时间和扣款结果。 |

本轮脚本验证旧规则基线；上述新模型场景应在实现后作为新的功能验收，不能复用旧脚本的通过数量宣称全部完成。

## 欧美目标用户验证方案

下一版先安排六至八名目标用户做形成性测试，覆盖美国与欧洲地区、现有设备用户及首次接触用户。欧洲样本注明具体国家和语言，不将其视为统一人群。该样本用于发现问题，不用于估计市场转化率或代表全部欧美用户。

使用隐藏评审工具的客户模式和模拟支付，不提供侧栏场景切换或直接页面地址。每个任务使用独立测试账户；观察员不提前解释会员、Credits 或标签含义。

| 任务 | 给用户的情境 | 完成后追问 |
| --- | --- | --- |
| 判断训练是否包含 | 找一项适合今天的训练，并判断能否直接开始。 | 你认为它是否另收费，为什么？ |
| 补充后完成分析 | 你想分析刚完成的训练，现有可用量不足，请完成这件事。 | 本次买到了什么？分析是否另有消费？未用完部分会怎样？ |
| 取消后找回已购内容 | 你不准备继续订阅，请取消续费，再找到之前单独解锁的训练。 | 什么时候失去会员？哪些内容和余额还会保留？ |

记录是否无需提示完成、首次选择是否正确、错误路径、求助、耗时及用户对实际收费和保留资产的解释。遇到失败后再追问原因，不在任务过程中教用户正确答案。

建议 Demo 验收门槛：三个任务均有完整正常与失败路径；参与者在准备消费前能准确判断本次费用；没有因误解产生的额外消费；取消后能区分有效期与续费状态。门槛作为下一版测试标准，不是本轮用户研究结果。
