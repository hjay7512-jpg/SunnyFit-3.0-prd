# Codex CLI task — SunnyFit V3.0 commercialization prototype

Read `SunnyFit_V3_Monetization_Codex_Context.md` in full. Treat it as a working prototype brief, NOT as approved product truth.

Build a runnable, API-connected frontend + backend prototype that validates the commercialization design (entitlement suits, commerce, membership, credits, gated content and AI service flows). First inspect the repository and use the linked current Figma files for visual grounding wherever access is available. Prefer an existing project stack if present; otherwise Vite + React + TS for frontend, Node + TS for backend, SQLite for local persistence.

Before coding, summarize architecture, file layout, MVP scenario coverage and the unconfirmed policy parameters you will place in demo config. Keep it brief. Then implement and run tests. Do not stop at a plan or a single static HTML file. Ensure mobile app and admin UI use the same API and persistent state. Keep business logic server-side. Do not connect real app stores or charge money. Label assumptions clearly.

Prioritize: (1) accurate domain model and access evaluation, (2) functioning end-to-end scenarios and admin state management, (3) UX fidelity to SunnyFit V3.0, (4) edge-case handling/tests, (5) concise README.

Output: source, lockfile, README, .env.example, seed/reset, tests, and exact run commands. Clearly flag any source conflicts / Needs Owner Confirmation, but use reversible demo assumptions to continue building.
