## 用户确认的业务规则

### 内容管理范围补充

用户进一步确认：“课程包”为现有 **Training Program**，不新增独立课程包类型。后台内容商业化管理包含 Course、World Tour、Training Program，对应 course_access、world_tour_access、training_program_access，支持标签筛选、单条编辑、批量草稿与发布。

Program Select 与包内课程 Start 的组合授权尚未确认。本稿先分别检查，Program 兑换不自动兑换包内 Featured，界面注明此口径待评审。完整实现和接口见 [开发交付说明](SunnyFit_V3_Admin_Prototype_Handoff.md)。

### 会员与 Credits 独立

- 会员是功能权益；Credits 是消耗余额。两个条件分别判断。
- 会员商品可以包含一定数量的 Credits 福利。会员购买产生权益授权，并按套餐规则发放对应 Credits，两项履约可分别追溯。
- 常规聊天、深入数据分析等需要调用 LLM 的功能消耗 Credits。拥有会员不代表这些调用自动无限免费。
- Credits 不足时可以加购。购买 Credits 本身不会自动获得会员专属功能。
- 对会员专属功能，新使用需要同时具备功能权益和足额 Credits；不需要会员的功能只需满足其基础授权及消费条件。

### 精品内容单独兑换或购买

- 特殊精品内容使用独立的兑换或购买流程，会员身份不能直接替代该流程。
- 成功后产生用户与具体内容关联的访问记录。
- 会员到期不撤销这项独立获得的内容资产。
- 内容授权检查必须区分会员范围和独立兑换记录，避免会员套餐中的 Scope ALL 绕过精品兑换。

精品兑换使用 Credits 还是现金、兑换权益的具体期限，尚未单独定值。根据既有工作稿，原型建议先演示 Credits 兑换，并明确这是演示口径。

### Credits 可以加购并按批次保留有效期

- 会员附赠、独立购买以及设备或活动赠送的 Credits 可以进入同一钱包显示。
- 每一次发放保留独立批次，记录来源、原始数量、剩余数量、发放时间、到期时间及关联商品或活动。
- 购买 Credits 的有效期与会员套餐赠送 Credits 的有效期分开配置。
- 可用总额是当前有效批次可用额度之和，过期批次不再可用。
- 会员结束不直接清空整个钱包；每批 Credits 按自己的到期时间判断。未到期的加购 Credits 不随会员到期失效。

### Credits 叠加并优先使用先到期的批次

- 不同来源的有效额度相加，消费优先扣减更早到期的批次。
- 一次消费允许跨多个批次，但保留每个批次的扣减明细。
- 到期时只处理对应批次，不清零其他有效余额。

实施建议：相同到期时间时优先消耗更早发放的批次；无到期时间的批次排在有到期时间的批次之后。后者仅在生产规则允许无期限余额时适用。

### 已购周期保留原规则

- 已购买会员在当前有效周期内保留购买时承诺的权益及 Credits 福利规则。
- 新购买采用当前发布的规则。
- 修改套餐不能直接覆盖正在履约的已购规则，也不能重写已有 Credits 批次的有效期。
- 后台需要区分编辑草稿和发布新版本，并展示影响对象。

实施建议：购买记录与权益授权关联不可变的配置版本。续费新周期是否采用最新版本，需要明确订阅渠道和产品政策后再确定；原型可以演示这一候选行为，不能视作已批准的生产续费规则。

### 到期后已有资产保留

- 已有对话、训练记录、计划、已生成分析与报告、独立兑换内容等数据资产保留。
- 查看已有数据不因会员到期而删除、重新收费或重新调用 LLM。
- 发起新的会员专属使用时重新检查权益；权益到期后限制该次新使用。
- 发起新的 LLM 使用时仍检查 Credits，并按实际消费规则处理。

例如，用户可以查看过去生成的 AI 报告；请求重新分析属于新使用，要再次检查该功能权益和 Credits。用户可以查看已有计划；激活新计划或发起需会员授权的调整，按当时权益判断。仅通过会员访问过的 Premium 课程，不等同于独立购买的内容资产，再次 Start 仍需检查当前访问权益。

## 功能判断和消费规则

该表把已确认的边界落实到操作。具体 Free、会员和 Additional Suit 包含哪些功能，由套餐配置确定，不在此预设所有 AI 功能均需要会员。

| 功能或操作 | 权限判断 | Credits 判断 | 已有结果的访问 |
| --- | --- | --- | --- |
| 免费课程 Start | 基础内容权限及内容可用状态。 | 单纯播放不调用 LLM，不因播放收取 LLM 消费。 | 训练历史保留。 |
| Premium 课程 Start | 当前有效的内容权益和 Scope，包含可适用的 Additional Suit。 | 单纯播放不扣 LLM Credits。 | 训练历史保留，再次播放检查当时权益。 |
| 精品内容首次兑换 | 内容可兑换及未重复兑换。 | 若采用 Credits 兑换，按明确报价检查并扣减；现金方案另行定义。 | 成功兑换形成独立访问记录。 |
| 精品内容重复播放 | 独立兑换记录及内容可用状态。 | 建议有效兑换后的回放不再收费。 | 不因会员到期失效。 |
| 常规 AI Chat | 对应聊天能力及 Text、Image、Live 范围。 | 发起 LLM 请求时消费 Credits。 | 查看已存对话不重新消费。 |
| 深入数据分析 | 对应分析能力，是否会员专属依套餐配置。 | 新分析调用 LLM 时消费 Credits。 | 查看已生成分析不重新消费。 |
| Dynamic Plan 讨论或生成预览 | 对话或生成能力；不把预览视作已激活。 | 如发生 LLM 调用，需要 Credits；读取已有预览不扣费。 | 已有预览和计划数据保留。 |
| Dynamic Plan Activate | Dynamic Plan 权益。 | 激活动作本身不应因名称自动收费；仅在实际触发需计费的 LLM 操作时判断消费。 | 新激活与读取旧计划分开。 |
| Workout Result AI Insight | 基础结果可读；新 AI 分析检查对应能力。 | 新生成或重新生成时消费 Credits。 | 基础结果和既有 Insight 保留。 |
| Weekly Report AI Insight | 基础周数据可读；新 AI 分析检查对应能力。 | 新生成或重新生成时消费 Credits。 | 基础周数据和既有 Insight 保留。 |

此前工作稿和 Alpha 设计中的 AI Chat 回合额度，需要改为与本次 Credits 模型一致。实施建议是将 User Turn 保留为使用统计，日常聊天的商业消耗使用 Credits；如要保留另一套独立的回合上限，应说明其用途和限制关系，不在原型中默认为会员付费额度。

## 新使用的处理顺序

1. 判断内容或功能当前是否可用，以及是否属于读取已有资产。
2. 新使用读取 Effective Entitlement，判断 Item 和 Scope。
3. 需要消费 Credits 的操作获得对应服务报价及价格版本。
4. 检查有效批次中的可用额度，按先到期先使用分配扣减。
5. 执行服务或兑换，记录结果、消费明细及关联资产。
6. 返回实际结果，App 更新余额并保留原功能上下文。

缺少功能权限时显示升级或获取对应权益；余额不足时显示加购 Credits。两者同时缺少时先解释权限限制，购买前明确完整使用条件，避免用户补充余额后才发现功能仍不可用。

处理失败、重复点击和请求重试的实施建议：服务端使用同一业务请求关联消费与结果；成功只能扣减一次，失败释放占用或返还对应批次；多个内部 LLM 或工具调用不重复创建用户的同一业务消费。内部成本计量和用户计价仍需与现有 Credits Catalog 对接确认。

## 原型技术与状态模型

采用 Vue 2 和 Element UI 实现后台，App 页面按 Figma 样式实现可交互的移动布局。Node API 与 SQLite 提供同一套持久状态，后台修改后可以直接看到 App 对应结果。

主要对象包括：User、EntitlementItem、SuitVersion、Product、SKU、Order、EntitlementGrant、EffectiveEntitlement、CreditBenefit、CreditBatch、CreditTransaction、CreditAllocation、ContentRedemption、ServicePricing、ServiceRequest、UserAsset 和 AuditEvent。

其中 SuitVersion 与购买时配置快照保护已购规则；CreditBatch 承载独立有效期；CreditAllocation 记录跨批次扣减；UserAsset 支持会员到期后读取已有成果。支付与 LLM 使用模拟服务，访问与消费由 API 执行。

建议文件结构：

```text
docs/                 业务规则、页面规格、接口和验收说明
frontend/admin/       后台布局与管理页面
frontend/app/         App 入口、钱包、内容和功能限制页面
server/               API、SQLite、授权和 Credits 服务
shared/               共享数据契约与访问原因
config/               明确标注的演示价格、额度和有效期
tests/                核心规则及流程验证
```

## 关键验收场景

1. 未购买会员的用户加购 Credits，可以使用已授予的基础聊天能力；加购不会自动开通会员专属功能。
2. 会员套餐发放 Credits，独立加购形成不同有效期的批次；总额正确相加。
3. 发起一次消费优先扣更早到期的批次，必要时跨批次扣减；流水能解释扣减来源。
4. 一批 Credits 到期只减少该批的可用余额，其他批次继续可用。
5. 会员仍有效但 Credits 不足时显示加购；Credits 充足但无对应功能权限时显示权益限制。
6. 精品内容需要单独兑换；有效兑换后重复访问不再次扣费，会员到期不移除兑换记录。
7. 套餐发布新版本后，现有已购周期保留旧权益及福利，新购买使用新版本。
8. 会员到期后仍可查看对话、计划、训练记录和已生成的 AI 分析；新的会员专属操作受限。
9. 已有报告的查看不消费 Credits；请求重新分析属于新的检查与消费。
10. 同一购买、兑换或服务请求重试，不重复发放或扣减；服务失败按方案释放或返还。

## 仍需定值的参数和对接规则

- Free 和会员各自包含哪些功能及 Scope；会员档位的最终名称。
- 会员及 Credits 商品价格、赠送或购买数量、具体有效期，以及月付或年付下的福利发放频率。
- LLM 服务使用固定价格、按 Token 计价或组合计价；与现有引擎 Catalog、预扣及实扣的关系。
- 精品内容的兑换币种和权益期限，旧 Star、Points 与历史订阅的实际映射。
- 自动续费的版本适用、升级结算、取消及退款，以及多个商店订阅并存时的处理。

原型中用集中配置的演示值呈现这些参数，并逐项标注。用户已确认的六项规则不作为可随意替换的演示假设。生产对接规则进入开发待办，原型演示不代表真实商店或 LLM 服务已经接通。
