# SunnyFit V3.0 高保真 Demo 和组件迭代方案

本地 Demo 应作为后续 V3.0 功能迭代的持续开发基础：复用正式 UI、真实业务状态和完整交互，新增提案在已有任务链中展示，并可通过固定场景重复验收。先建立一条完整、高保真的页面任务链，再逐步提炼和扩展组件。

首批组件与本地实验工具已落地，实际范围及未完成项见[组件材质与后续更新](SunnyFit_V3_Liquid_Glass_And_AI_Update.md)。已通过已授权的远程 Figma 工具取得正式首页 7590:5619 的完整上下文和 31 项资源，默认首页已组合共用组件。个人计划、签到、历史与数据图表的完整数据契约、活跃计划整页和其余页面迁移仍未完成。

首页现已使用 `V3Home.vue` 编排共用导航、课程、计划、数据和空状态组件；旧首页源稿留作历史参考。其余训练、课程和结果页面仍依赖生成类名与多层样式覆盖，必须逐页继续迁移。既有布局和交互检查不能代替正式设计视觉验收。

## 组件的分层与边界

| 层次 | 建议维护内容 | 约束 |
| --- | --- | --- |
| 样式基础 | 语义颜色、字体与字重、字号与行高、间距、圆角、阴影、背景和层级 | 从正式上下文提取，附设计来源；未经读取的值不当作已确认规范 |
| 基础组件 | Button、Icon、Tabs、Header、BottomNavigation、Sheet、Dialog、Input、Feedback | 明确尺寸和状态；图标复用原资产；标签页、导航、弹层保持各自交互语义 |
| 业务组件 | WorkoutCard、PlanCard、ProgressCard、CourseCard、MembershipCard、UsageMeter | 数据通过 props 提供，业务动作通过事件传出；保留各自真实设计差异 |
| 页面与任务链 | Home、课程详情、计划、AI Coach、个人中心及商业化页面 | 页面编排组件；业务规则和接口调用不塞进视觉组件 |

组件候选来自设计中的重复结构，名称和最终边界在高保真上下文核对后确定。只出现一次、差异很大的模块先留在页面中，不为了通用而增加大量条件。前台采用自己的正式设计规范，后台继续复用现有后台 UI。

## 本地维护方式

沿用当前 Vue 2 技术栈和本地服务，第一阶段不同时升级框架。建议逐步建立以下目录：

```text
src/design-system/tokens/    有来源的样式基础
src/design-system/components/ 基础组件
src/features/               业务组件和页面
src/demo/scenarios/         固定场景、数据和状态切换
docs/design-baseline/       页面来源、截图和差异记录
```

保留已有商业化接口、额度规则与购买链路；迁移时按页面替换旧 UI，并在确认该页不再依赖原选择器后移除对应覆盖样式。评审工具和组件展示页独立于产品页面，不添加新的用户入口。

组件展示应包含原稿出现的状态及实现所需状态，例如普通、选中、禁用、加载、长文本、空数据和错误。未在原稿中定义的视觉状态单独标为待确认。演示数据可重置、可重复，模拟支付和 AI 的说明放在评审工具中。

## 迁移顺序与每步交付

1. **基线盘点**：建立页面与设计节点映射，记录正式稿和 Alpha 的关系；整理静态资源、字体和页面状态。重复或冲突设计不悄悄选取其一。
2. **首页作为首个还原样板**：以已读取的默认首页为候选基线，核对其完整设计上下文；还原首页到课程详情再返回的任务链。交付同尺寸截图比对、可点击路径及从该页面提炼的首批组件。
3. **组件展示与首页状态**：补齐按钮、分段切换、卡片、导航等展示，并验证已有计划、无计划、日程等设计状态。各状态均由固定场景驱动。
4. **逐页迁移**：训练与计划、AI Coach、个人中心和商业化页面逐步接入。同一组件用于相同结构，业务规则继续独立维护。
5. **后续功能提案**：声明已有入口、业务状态和所需新增组件；在任务链中实现，更新固定场景和验收截图，检查对旧页面的影响。

每一步交付都包含浏览器入口、对应 Figma 来源、可复现的状态、截图比对及未完成项。首批完整任务链验收后再扩展其他页面。

## 验收要求

- **视觉**：按原稿对应宽度比较截图，核对字体、间距、背景、图片裁切、图标、固定区域和弹层。375、390、430 宽度无溢出只是适配要求，不能据此宣称高保真。设计源图和 Demo 数据须一致，动态内容另作场景验证。
- **资源**：每个可见静态资源都有非空本地文件，位置与实际渲染尺寸符合原稿，不用相似图标或占位图冒充完成。
- **交互**：原有入口、返回、滚动、输入、键盘与焦点、加载和失败反馈可用，状态切换不丢失任务上下文。
- **业务**：免费基础功能、会员权益、服务次数、Credits、确认超额支付与原任务返回保持已确认规则；演示参数与生产规则分别标识。
- **回归**：组件修改检查其受影响的页面，保留业务关键链路检查；截图差异需要评审，不能直接覆盖基准使检查通过。
